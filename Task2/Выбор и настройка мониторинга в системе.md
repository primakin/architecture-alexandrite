# Мотивация
Мониторинг позволит оперативно замечать и реагировать на проблемы еще до того, как с ними столкнутся пользователи, а это улучшит пользовательский опыт. Например, о задержках выполнения заказов мы бы узнали через дашборд, а не от клиентов.

Также мониторинг поможет лучше понимать, что происходит с БД, приложениями и очередью сообщений. Это ускорит решение проблем и поможет предотвратить их в будущем.

# Выбор подхода к мониторингу
- USE для БД, MES и будущего сервиса расчета стоимости заказов (отслеживаем использование ресурсов).
- RED для очереди сообщений и API (отслеживаем скорость обработки запросов и ошибки).

# Список метрик
## БД
- Memory Utilisation for MES db instance
	- высокое значение может говорить о тяжелых запросах и/или нехватке памяти, низкое - о неправильной конфигурации (например, СУБД не использует доступную память, что может приводить к лишним операциям ввода-вывода).
- Connections Used % for MES db instance
	- высокое значение говорит о том, что скоро клиентам может быть отказано в новых подключениях к БД (например, по причине роста нагрузки, тяжелых запросов или утечки соединений в приложении).
- Size of MES db instance
	- рост говорит о том, что пора увеличивать размер БД или подумать о шардировании.

## MES
- CPU % for MES
	- высокое значение - показатель тяжелых расчетов, надо подумать об оптимизации расчетов и/или вертикальном масштабировании.
- Memory Utilisation for MES
	- высокое значение так же говорит о тяжелых расчетах и нехватке ресурсов (а может и об утечке памяти).

## Очередь сообщений
- Number of dead-letter-exchange letters in RabbitMQ
	- показывает количество отклоненных сообщений, может служить индикатором переполнения очереди или задержек в обработке.
- Number of message in flight in RabbitMQ 
	- рост количества сообщений говорит о том, что MES не успевает обрабатывать заказы.

## API
- Number of requests (RPS) for MES API
	- показывает нагрузку на MES API
	- ярлыки: method, url, code 
- Number of requests (RPS) for CRM API
	- показывает нагрузку на CRM API
	- ярлыки: method, url, code 
- Response time (latency) for MES API
	- показывает задержку ответов на запросы
	- ярлыки: method, url, code
- Response time (latency) for CRM API
	- показывает задержку ответов на запросы
	- ярлыки: method, url, code
- Number of HTTP 500 for MES API
	- показывает количество ошибок при обработке запросов
	- ярлыки: method, url
- Number of HTTP 500 for CRM API
	- показывает количество ошибок при обработке запросов
	- ярлыки: method, url

# План действий
1. Создать инстанс сервера Prometheus, настроить список сервисов для сбора метрик.
2. Создать инстанс Grafana, настроить интеграцию с Prometheus.
3. Реализовать отправку метрик в приложениях, БД и очереди сообщений.
4. Настроить дашборды в Grafana, добавить метрики.

# Показатели насыщенности
- Memory Utilisation for MES db instance
    - 95%. Если утилизация >95% и при этом растет swap - нехватка памяти, нужно масштабирование.
- Connections Used % for MES db instance
    - 50%. При превышении завести тикет или написать письмо для проверки пула соединений и долгих транзакций.
