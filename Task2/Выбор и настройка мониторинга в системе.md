# Мотивация
Мониторинг позволит оперативно замечать и реагировать на проблемы еще до того, как с ними столкнутся пользователи, а это улучшит пользовательский опыт. Например, о задержках выполнения заказов мы бы узнали через дашборд, а не от клиентов.

Также мониторинг поможет лучше понимать, что происходит с БД, приложениями и очередью сообщений. Это ускорит решение проблем и поможет предотвратить их в будущем.

# Выбор подхода к мониторингу
- USE для БД, MES и будущего сервиса расчета (отслеживаем использование ресурсов).
- RED для очереди сообщений и API (отслеживаем скорость обработки запросов и ошибки).

# Список метрик
## БД
- Memory Utilisation for MES db instance
- Connections Used % for MES db instance
- Size of MES db instance

## MES, сервис расчетов
- CPU % for MES
- Memory Utilisation for MES

## Очередь сообщений
- Number of dead-letter-exchange letters in RabbitMQ
	- показывает количество отклоненных сообщений, может служить индикатором переполнения очереди или задержек в обработке
- Number of message in flight in RabbitMQ 
	- рост количества сообщений говорит о том, что MES не успевает обрабатывать заказы


## API
- Number of requests (RPS) for MES API
	- показывает общую нагрузку на MES API
	- ярлыки: method, url, code 
- Number of requests (RPS) for CRM API
	- показывает общую нагрузку на CRM API
	- ярлыки: method, url, code 
- Response time (latency) for MES API
- Response time (latency) for CRM API
- Number of HTTP 500 for MES API
- Number of HTTP 500 for CRM API
