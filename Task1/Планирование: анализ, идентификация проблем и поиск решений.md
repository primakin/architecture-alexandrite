# Существующие и потенциальные проблемные места
- Низкая скорость расчета моделей в MES, расчет происходит синхронно и является узким местом в цепочке обработки заказов.
- Линейный рост количества заказов приводит к задержкам/потерям заказов.
- Непонятна надежность интеграции через RabbitMQ, возможно, что в очереди теряются сообщения.
- Долгая загрузка списка заказов в MES.
- Каждое приложение имеет по одному инстансу, отсутствует горизонтальное масштабирование.
- Базы данных имеют по одному инстансу, который работает и на запись, и на чтение (отсутствуют реплики для чтения).
- Ручной деплой в релиз-окружение и продакшн.
- Потенциальная нехватка компетенций в React для MES фронтенда (только один разработчик "частично знает" React), по C# тоже может не хватать ресурсов (один бэкенд разработчик и частично тимлид), в перспективе это может тормозить работу над MES.
- Ручное тестирование E2E-сценариев силами одного QA, юнит и интеграционное тестирование отсутствуют, что приводит в т.ч. к задержкам релизов. 
- Отсутствуют мониторинг, трейсинг и логирование, проблемы обнаруживаются через обращения клиентов, а не проактивно.
- Статусы заказа меняются в разных системах, нет единого источника истины.
 
# Инициативы, которые необходимы для устранения нежелательных ситуаций (в порядке приоритета)
1. Внедрение мониторинга, трейсинга и логирования.
2. Диагностика и решение проблемы задержки/потери заказов (выделение сервиса расчета стоимости, расчет должен выполняться асинхронно). 
3. Оптимизация дашборда MES (кеширование, репликация БД для чтения).
4. Автоматизация тестирования E2E-сценариев (силами QA или с наймом SDET).
5. Автоматизация деплоя.
6. Горизонтальное масштабирование приложений.
7. Выделение сервиса заказов как единого источника истины по статусам заказов. 

# Целевая архитектура через полгода
- Приложения (CRM, MES и онлайн-магазин) масштабированы горизонтально.
- Выделены сервис заказов и сервис расчета стоимости.
- БД реплицирована, реализовано кеширование.
- Деплой автоматизирован.
- Внедрены мониторинг, трейсинг и логирование.

# Три пункта из списка инициатив в ближайшие полгода
- Внедрение мониторинга трейсинга и логирования позволит оперативно реагировать на проблемы и быстрее фиксить баги.
- Решение проблемы задержки/потери заказов улучшит пользовательский опыт и положительно повлияет на бизнес.
- Оптимизация дашборда MES позволит операторам быстрее обрабатывать заказы.
